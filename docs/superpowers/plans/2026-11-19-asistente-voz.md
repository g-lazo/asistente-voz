# Voice Task Assistant (POC) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Flutter app (Android emulator and Chrome) where a signed-in user holds a microphone button, says a task in Spanish, and the task is stored in Firestore and listed.

**Architecture:** One Flutter project at the repo root. All logic that can be pure is pure Dart (phrase parser, date labels, replies, sorting). Plugins (speech, text-to-speech, Firestore, Auth) sit behind small interfaces so the assistant's behaviour is unit tested with fakes. Everything runs inside one long-lived Docker container; the host only has Docker.

**Tech Stack:** Flutter 3.50.0 (Dart 3.14.0), `firebase_core`, `firebase_auth`, `cloud_firestore`, `speech_to_text`, `flutter_tts`, `shared_preferences`, Android SDK + emulator (API 34 Google Play x86_64 image), Firebase CLI, FlutterFire CLI, Docker Compose, Make.

**Spec:** `docs/superpowers/specs/2026-11-19-asistente-voz-design.md`. Read it before any task. Mockups: `docs/mockups/` (layout B of `main-screen-options.html`).

## Global Constraints

- Nothing is installed on the host. Every `flutter`, `dart`, `adb`, `firebase` command runs through `make` or `docker compose exec dev ...`.
- UI text in Spanish (Mexico). Code, comments, commit messages and docs in English. No emojis anywhere.
- Commits: one per task, tests green, message in Conventional Commits style, no signature, no attribution footer, never `-c user.name` / `-c user.email`.
- Git is local only. Never push, never add a remote.
- Never type or read credentials. Interactive logins and the Firebase console are Gustavo's.
- Ask Gustavo before: accepting the Android SDK licenses, starting the first image build (several GB), deploying Firestore rules.
- Do not add the patterns Gustavo left out: confirmation card with Undo, suggestion chips, animated waveform.
- Out of scope (spec section 4): iOS, voice commands other than adding, times of day, editing tasks, saved chat history, Google sign-in, password reset.
- Not in this plan: day numbers spelled out ("veinticinco"). The spec marks them nice-to-have and first to cut.
- Never leave a container, emulator or `flutter run` process running at the end of a task unless the task says so.
- Tests: `flutter test <path>` for the files a task touches while iterating; `make test` and `make analyze` clean before each commit.

## Review Focus

1. The recognizer returns text with a capital first letter, a trailing period, or without accents ("Agrega comprar leche.", "recuerdame ... el miercoles"). Expected: same task as the clean phrase. Test in Task 3.
2. A date-looking ending that leaves a dangling word, or a date that does not exist ("comprar el periódico de hoy", "el 31 de febrero"). Expected: no dangling "de"; an impossible date stays in the title and the task has no date. Test in Task 3.
3. The write to Firestore is never acknowledged (offline). Expected: after 10 seconds the assistant says it could not save, and the task does not appear later. Test in Task 6.
4. The person presses the microphone again while the previous phrase is still being saved, or taps it too briefly to say anything. Expected: no duplicate task, no stuck button, "No te entendí" for the empty press. Test in Task 7.
5. The recognizer stops by itself on a pause while the button is still held, and the person keeps talking. Expected: both parts end up in the transcript. Test in Task 7 (`TranscriptAccumulator`) and in the manual checklist.

### Task 3: Phrase to task

**Files:**
- Create: `lib/assistant/command_parser.dart`
- Test: `test/assistant/command_parser_test.dart`

**Interfaces:**
- Produces:

```dart
class ParsedTask {
  const ParsedTask({required this.title, required this.heard, this.dueDate});
  final String title;       // 1 to 200 characters, first letter upper-case
  final DateTime? dueDate;  // DateTime(y, m, d), no time
  final String heard;       // the transcript, trimmed
}

/// Returns null when the phrase holds no task. Only the date part of [today] is used.
ParsedTask? parseCommand(String transcript, DateTime today);
```

Rules the spec leaves open, decided here:

- Match on a folded copy of each word (lower-case, `áéíóúü` to `aeiouu`, `ñ` to `n`, surrounding punctuation dropped). The title is built from the original words.
- Trigger, first word only: `agrega`, `agregar`, `anade`, `anadir`, `anota`, `anotar`, `recuerdame`. Connector right after it, longest first: `la tarea de`, `una tarea de`, `la tarea`, `una tarea`, `que`.
- A date phrase counts only at the very end or the very start of what is left. Forms: `[para] hoy|manana|pasado manana`; `[para] el|este <weekday>` (the article is required, so "ver a Domingo" is not a date); `[para] [el] <1-31> de <month>`.
- Weekday: days ahead = `(target - today.weekday + 7) % 7`, and 0 becomes 7.
- Day and month: this year; if that day is before today, next year; if the date does not exist, it is not a date and the words stay in the title.
- After removing the date, drop trailing words `para`, `de`, `el`, `este`.
- Title: words joined by one space, leading and trailing `. , ; : ! ? ¿ ¡ "` removed, first letter upper-cased, cut to 200 characters.

`HomeScreen` gains three required parameters: `SpeechInput speech`, `VoiceOutput voice`, `MuteSetting mute`. It owns the controller and adds the mute toggle to the app bar (tooltips "Silenciar voz" / "Activar voz"). `main.dart` loads `SharedPreferences` and passes `SttSpeechInput()`, `TtsVoiceOutput()`, `MuteSetting(prefs)`.

Controller behaviour:

- `pressStart`: ignored unless idle. Stops the voice, then `speech.prepare()`. `permissionDenied` adds `replyMicDenied`, `unavailable` adds `replySpeechUnavailable`, both stay idle. Otherwise `speech.start`, state `listening`, `partial` follows `onText`.
- `dragUpdate`: `dx <= -80` gives `cancelArmed`; back above -80 gives `listening`.
- `pressEnd` when `cancelArmed`: `speech.cancel()`, no message, hint "Cancelado" for 1.5 seconds, then idle.
- `pressEnd` when `listening`: `speech.stop()`. Empty text adds `replyNotUnderstood`. Otherwise add the user bubble, state `busy`, `parseCommand(text, now())`; null adds `replyNotUnderstood`; a task goes to `tasks.add`, success adds `replySaved(task, pending)`, an error adds `replySaveFailed`. Back to idle.
- `pending` is `pendingCount` of the latest list from `tasks.watch()`, which the controller subscribes to; it already contains the new task when `add` completes.
- Every assistant bubble is passed through `spokenText` to `voice.speak` unless `muted.value`.
- Hints: idle "Mantén presionado para hablar"; listening "Suelta para enviar · desliza a la izquierda para cancelar"; cancelArmed "Suelta para cancelar"; busy "Guardando...".

`SttSpeechInput`: Spanish locale as found in the spike. While the button is held, if the recognizer reports it stopped, call `listen` again; the `TranscriptAccumulator` keeps what was already heard. `TtsVoiceOutput`: language `es-MX`, falling back to `es-ES`.

Assistant tab: bubbles like the mockup (user right, assistant left), newest at the bottom and scrolled into view; above the button the partial transcript (key `partialText`); the button (key `micButton`) inside a `Listener` that maps pointer down, move and up/cancel to `pressStart`, `dragUpdate`, `pressEnd`; the hint (key `hint`). The button looks different while listening and while armed to cancel.
